# M6 联调与部署

M6 已将现有采集、AI、Decision Engine 和通知链路接入运行进程。当前首个合法公开源使用 CNBC RSS；可通过 `NEWS_SOURCE_URL` 替换为已授权的金十接口。

## 配置

```powershell
Copy-Item .env.example .env
```

至少设置：

- `ENABLE_CRAWLER=true`
- `ENABLE_AI=true`
- `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`
- `ENABLE_PUSH=true`
- `WECOM_WEBHOOK_URL`

可调整 `NEWS_SOURCE_URL`、`MAX_ITEMS_PER_CYCLE`、`COLLECT_INTERVAL_SECONDS`、`PUSH_MIN_IMPORTANCE`、`QUIET_HOURS_START` 和 `QUIET_HOURS_END`。

## 启动

```powershell
docker compose up --build
```

Compose 会先执行 Alembic 迁移，然后启动 API 和持续运行的 worker。worker 每个周期执行：

```text
RSS/Source Adapter -> RawNews -> NewsItem/Event -> AI Pipeline -> Event importance -> Decision Engine -> WeCom -> PushDelivery
```

## 单次演示

配置 `.env` 后可在已有 PostgreSQL/Redis 环境运行：

```powershell
python -m app.run_once
```

成功时日志会包含采集数量、新闻 ID、Event ID 和推送结果；企业微信消息由机器人直接发送到对应群聊。

## 已知问题与边界

- 当前工作区没有 `.env`、Docker、PostgreSQL、Redis、AI API Key 或企业微信 Webhook，因此尚未完成真实 AI 调用和微信收信验收，不能宣称端到端已成功。
- RSS 首次启动只处理 `MAX_ITEMS_PER_CYCLE` 条，游标记录最新一条，避免首次运行产生大量 AI/推送成本。
- AI Provider 网络/认证失败和响应校验失败都会进入 `ai_review_queue`；后续可增加更细的 Provider 错误审计和自动退避。
- CNBC RSS 内容和访问策略可能变化；生产环境应使用拥有明确授权和稳定 SLA 的数据源。

## 后续优化建议

先在目标机器配置真实凭据并完成一次 `python -m app.run_once`，确认 AI 输出和企业微信消息后再开启长期 worker；随后再考虑 Web 后台、监控告警和多数据源扩展。
